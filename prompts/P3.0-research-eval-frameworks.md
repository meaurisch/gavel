## Context

I'm building **setup-bench**, a local-first benchmarking framework for comparing
agentic coding setups. It measures how different instruction/skill packs
(e.g., Anthropic's superpowers, Karpathy's guidelines, ECC agent OS) affect code
quality when given to AI coding agents (Claude Code, GitHub Copilot CLI).

The framework runs each (setup × model × task) combination in an isolated git
worktree, captures the diff, runs held-out tests, and presents blind pairwise
comparisons to a human grader. It's a **personal decision-support tool**, not a
published benchmark — think structured due diligence for choosing your coding
setup, not a scientific paper.

Current state: the core engine works (worktree isolation, runner abstraction,
held-out test gating, blind pairwise UI with anonymized diffs, cost tracking).
I have 3 evaluation tasks extracted from the PyVRP repository. I'm now evolving
the architecture based on colleague feedback and need research to guide the
decisions.

## Research Questions

Please investigate each area thoroughly. For each, I want: what exists, how it
works, what's good about it, what its limitations are, and what setup-bench
should learn from it.

### 1. Claude Code's built-in evaluation system

Claude Code (Anthropic's CLI coding agent) has some kind of built-in evaluation
or testing framework for skills/instructions. I need to understand:

- What is it exactly? How does it work?
- What's its task format? How are evaluation instances defined?
- How does it score results — automated tests, LLM-as-judge, or human review?
- What's its scope — is it only for testing Claude Code skills, or more general?
- How does it handle non-determinism (multiple runs, pass@k)?
- What can setup-bench learn from its design? What should we avoid?

### 2. SWE-bench and its methodology

SWE-bench is the closest public benchmark to what I'm building. I need a deep
understanding:

- How does SWE-bench construct evaluation instances from real GitHub repos?
- How does it select tasks — what makes a task discriminative vs too easy/hard?
- How are held-out tests designed? What makes them robust?
- How does it handle the difference between "system instructions" and
  "repo-specific context"?
- How does it gate results (pass/fail vs partial credit)?
- How does it handle non-determinism — do they run multiple times?
- SWE-bench Verified, Lite, Full — what are the differences and why?
- What are the known criticisms of SWE-bench? What pitfalls should I avoid?

### 3. Other relevant evaluation frameworks

Survey what else exists in the LLM code evaluation space:

- HumanEval, MBPP, EvalPlus — how do they differ from SWE-bench?
- LiveCodeBench, BigCodeBench — newer alternatives?
- Any frameworks specifically designed for evaluating *instruction sets* or
  *agent configurations* rather than just model capabilities?
- pass@k methodology — how is it applied in practice for code generation?

### 4. Best practices for evaluation task design

Drawing from all the above, what makes a good evaluation task for my use case
(comparing coding setups, not just models)?

- What makes a task **discriminative** — able to separate good setups from bad?
- How do you balance task difficulty to avoid ceiling/floor effects?
- How should visible vs hidden tests be structured?
- What's the right ratio of easy/medium/hard tasks in a test suite?
- How many tasks do you need for reliable signal?
- What anti-patterns should be avoided (tasks that are too toy, too dependent on
  memorization, too underspecified, etc.)?

### 5. Cost and efficiency measurement in benchmarks

- How do existing benchmarks report computational cost?
- Is there a standard approach for cost-quality frontier analysis?
- How do they handle the fact that different models have different per-token
  costs?
- Any interesting approaches to measuring "efficiency" beyond raw USD?

### 6. Multi-trial aggregation and comparison methodology

- How do benchmarks aggregate results across multiple runs?
- Pairwise comparison (Bradley-Terry, Elo) vs direct scoring — trade-offs?
- How do benchmarks present results to users? Tables, Pareto charts, rankings?
- What's the minimum number of repetitions the literature recommends for
  reliable signal in code generation tasks?
