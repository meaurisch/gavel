## Context

After P3.3 Part 3, grading is **axis-general**: `generate_pairs(trials, axis, …)`
picks rep 0 from each **value of the chosen comparison axis** (methodology /
model / repo-context / runner) within a fixed cell and generates C(N,2) pairwise
comparisons. This wastes the data from reps 1, 2, etc. and gives no statistical
picture of uncertainty.

The research report (`docs/research-eval-frameworks.md` §6) says: *"Bradley-
Terry maximum-likelihood model"* is the standard for converting pairwise
judgments into a global ranking (used by LMSYS Chatbot Arena with 130k+ votes).
BT gives transitivity (beating a strong opponent counts more), stability with
unbalanced match counts, and confidence intervals via bootstrap. The research
also recommends analyzer heuristics from skill-creator: flag non-discriminating
tasks, flaky tasks, and cost/quality tradeoffs.

## What to build

### 1. Rewrite `generate_pairs()` — `grading/pairwise.py`

Replace the current rep-0 selection with balanced multi-rep sampling.

**Current behavior (after P3.3 Part 3, in `grading/pairwise.py`):**
- Groups trials by the chosen comparison axis (`getattr(t, AXIS_FIELDS[axis])`)
- Picks the trial with the lowest rep number per axis value
- Generates all C(N,2) combinations of representatives

**New behavior — keep the `axis` parameter, add multi-rep sampling:**
```python
def generate_pairs(
    trials: list[Trial],
    run_results: dict[str, RunResult],
    axis: str = "methodology",
    num_pairs: int | None = None,
    seed: int | None = None,
) -> list[tuple[Trial, Trial]]:
```

Logic (M = distinct values of the comparison axis in the cell, R reps each):
1. Group trials by the comparison axis (`getattr(t, AXIS_FIELDS[axis])`).
2. Build the full candidate pool: all pairs `(a, b)` where `a` and `b` are from
   **different axis values**, across all reps. For M values with R reps each,
   this is `C(M,2) × R × R` candidates.
3. If `num_pairs` is None, default to `C(M,2) × 3` (3 comparisons per axis-value
   pair — enough for BT to work).
4. Sample `num_pairs` from the candidate pool using seeded RNG, with **balanced
   rep usage**: track how many times each trial has been selected, and prefer
   under-represented trials. A simple approach: shuffle candidates, then greedily
   pick the next candidate that uses the least-used trial.
5. Randomly assign left/right (50/50, seeded).

This ensures every rep has a chance to be compared, not just rep 0.

### 2. Create `grading/bradley_terry.py` — BT model + bootstrap

Implement a minimal Bradley-Terry model. No external ML libraries — just numpy.

```python
import numpy as np

    # Each tuple: (winner_id, loser_id, outcome) where ids are comparison-axis values
    # outcome: "win" (first beats second), "loss", or "tie"
) -> dict[str, float]:
    """Fit BT model, return log-strength per comparison-axis value. Ties count as 0.5 win each."""

def bootstrap_ci(
    comparisons: list[tuple[str, str, str]],
    n_bootstrap: int = 1000,
    ci: float = 0.95,
    seed: int | None = None,
) -> dict[str, tuple[float, float, float]]:
    """Bootstrap confidence intervals. Returns {id: (lower, median, upper)}."""

def bt_scores_to_elo(strengths: dict[str, float], base: float = 1000.0, scale: float = 400.0) -> dict[str, float]:
    """Convert BT log-strengths to Elo-style scores for display."""
```

**BT fitting algorithm:**
1. Initialize all strengths to 0 (log-scale).
2. For ties: count as half-win for each side (LMSYS convention).
3. Iterative MLE (MM algorithm):
   - For each axis value `i`, count wins `w_i` and total comparisons `n_ij`
     against each opponent `j`.
   - Update: `strength_i = log(w_i / sum_j(n_ij / (strength_i + strength_j)))`
   - Repeat until convergence (< 1e-6 change) or max 100 iterations.
4. Normalize so the mean strength is 0.

**Bootstrap:**
1. Resample comparisons with replacement (1000×).
2. Fit BT on each resample.
3. Return 2.5th and 97.5th percentiles as 95% CI.

**Elo conversion:** `elo_i = base + scale × strength_i / ln(10)` — this gives
human-readable scores centered around 1000.

### 3. Add analyzer flags — `grading/analyzer.py` (new)

Implement the three analyzer heuristics from skill-creator, keyed by the
**comparison-axis value** (the methodology-specific phrasing below applies when
`axis="methodology"`; substitute the chosen axis's values otherwise):

```python
@dataclass
class AnalyzerFlags:
    non_discriminating_tasks: list[str]   # task IDs where all axis values pass or all fail
    flaky_tasks: list[str]               # task IDs with high variance across reps
    cost_quality_notes: list[str]        # free-text observations

def analyze(
    trials: list[Trial],
    gate_results: dict[str, GateResult],
    cost_records: dict[str, CostRecord],
    axis: str = "methodology",
) -> AnalyzerFlags:
```

Logic (with `value = getattr(trial, AXIS_FIELDS[axis])`):
- **Non-discriminating:** For each task, compute pass rate per axis value. If all
  values have 100% or all have 0%, flag the task.
- **Flaky:** For each (task, axis value), if pass rate across reps is between
  20%–80%, flag as high-variance (that value doesn't reliably pass or fail).
- **Cost/quality:** Find the cheapest axis value that passes and the most
  expensive. If they have similar pass rates, note that the expensive one doesn't
  justify its cost.

## What NOT to do

- Don't implement automatic BT-based selection of the winning axis value — BT
  scores are for display, not automated decisions.
- Don't add significance tests (p-values, Holm-Bonferroni) — the CIs are enough
  for decision support.
- Don't add persistent BT scores to the database — they're computed on the fly
  from judgments.

## Verification

1. Unit test for BT: create synthetic comparisons where A always beats B, B
   always beats C. Verify `fit_bradley_terry()` ranks A > B > C.
2. Unit test for ties: all ties → all scores should be equal.
3. Unit test for bootstrap: verify CI bounds bracket the point estimate.
4. Integration test: run the grading UI, make some judgments, reveal — verify BT
   scores appear in the response.
5. Verify balanced sampling: with 3 axis values × 3 reps, `generate_pairs(…,
   axis=…)` should use all reps, not just rep 0 (test with at least one non-default
   axis, e.g. `axis="model"`).
6. Verify analyzer flags: create a scenario where one task has 100% pass rate —
   verify it's flagged as non-discriminating.
