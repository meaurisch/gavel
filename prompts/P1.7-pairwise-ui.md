# P1.7 — Blind pairwise grading UI

> **Superseded by** [`P3.3-part3-grading-axis.md`](P3.3-part3-grading-axis.md)
> (axis-general grading — pick any axis as the comparison target, blind every
> axis id) **and** [`P3.5-multi-rep-pairwise.md`](P3.5-multi-rep-pairwise.md)
> (multi-rep sampling + Bradley-Terry ranking). This prompt built the original
> methodology-only grading UI (done); the P3.x prompts evolve it. Build from
> those, not this, for the current design.

> **Studio adjustment.** FastAPI matches studio's "well-known frameworks for
> Python backends" guidance. The app lives under `ui/`. Also add a
> `tasks.ps1 Grade` (or `Ui`) function to launch it once it exists.

```
Build ui/ as a minimal local web app (FastAPI + a single static page; no auth, localhost only). It reads from results.db and, for a chosen task + model, generates all blind pairwise comparisons among setups that PASSED the gate (failures are excluded — they're already out). 
For each comparison it shows diff A and diff B SIDE BY SIDE, anonymized (strip any setup-identifying paths/markers; randomize left/right), and asks one question: "Which would you merge? A / B / Tie." Optionally record the 4-dim rubric (correctness, diff-minimality, readability, over-engineering) as quick notes — recorded, never summed. Store each judgment with the hidden setup identities. Keyboard-first: A/B/T to choose, arrow to advance. Show the alongside objective proxies for each diff (lines changed, files touched, new deps) but keep them visually secondary. After grading, reveal identities and persist a judgments table.
The whole point is speed and pleasure — make one comparison take seconds, not minutes.
```
