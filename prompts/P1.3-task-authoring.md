# P1.3 — Task authoring (revert + held-out tests + leakage)

> **Studio adjustment.** Tasks are written under `tasks/<id>/` in this package.
> Reuse `grading/leakage.py` from P0.3 rather than re-implementing the scan.
> Multi-step + careful — `studio-conductor` plans, `studio-executor` executes.

```
Author a setup-bench task from a chosen merged feature. Given repo path, the feature's commit SHA, and the list of test files covering it:
1. Compute base_commit = the commit's parent. Save the feature's full diff as tasks/<id>/reference.diff.
2. Create a clean revert on a fresh branch so base_commit represents "feature absent." Verify the repo builds with the feature absent and that the covering tests now FAIL (proving they actually test the feature).
3. Move the covering tests into tasks/<id>/held_out_tests/ and STRENGTHEN them: add edge cases / assertions so a plausible-but-wrong implementation cannot pass. Show me the original vs strengthened tests.
4. Write tasks/<id>/task.yaml: instruction (a realistic feature request in my words, NOT a description of the original implementation), repo_url, base_commit, run_cmd, held_out_tests_path, reference_diff_path.
5. Run grading/leakage.py with the feature's symbol/file/test names as feature_terms and show me every hit to clear.
Report whether oracle passes the strengthened gate and nop fails it.
```
