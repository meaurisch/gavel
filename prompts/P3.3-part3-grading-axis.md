## Context

setup-bench has a 5-axis trial matrix: **Task × Methodology × Repo-Context ×
Model × Runner** (with reps). Grading is still **methodology-only**:
`grading/pairwise.py` `generate_pairs` groups hardcoded by `methodology_id`,
`anonymize_diff` only redacts methodology ids, and the UI grades within a fixed
`(task, model)` and reveals per methodology.

The user wants **comparison to be axis-general**: the grader picks *which* axis
to compare (methodology / model / repo-context / runner); that axis varies while
**every other axis is held fixed** as the "cell"; pairs are grouped and tallied
by the chosen axis; and the diffs redact **every** axis id so blind A/B works no
matter which axis is under test. Methodology is just the default.

Concretely, a **comparison axis** is one of `methodology | model | repo_context |
runner`. A **cell** is one fixed combination of `task_id` plus the other three of
those four axes (task is always fixed — different tasks solve different problems,
so their diffs aren't comparable). Within a cell the comparison axis takes ≥2
distinct values; pairwise grading compares those values blind.

## What to build

### 1. `grading/pairwise.py` — parameterize on the comparison axis

Map each comparison axis to its `Trial` field:

```python
AXIS_FIELDS = {
    "methodology": "methodology_id",
    "model": "model",
    "repo_context": "repo_context_id",
    "runner": "runner",
}
```

- **`generate_pairs(trials, run_results, axis, seed=None)`** — group by
  `getattr(t, AXIS_FIELDS[axis])` instead of hardcoded `methodology_id`. Keep the
  current rep-0-representative + `C(N,2)` + seeded left/right-flip behavior
  (multi-rep sampling + Bradley-Terry come later in P3.5). **Docstring invariant:**
  *callers pass exactly one cell's passing trials — i.e. all other axes already
  fixed — so the only thing that varies across the group is the comparison axis.*

- **`anonymize_diff(diff, axis_ids_by_axis)`** — change the signature from
  `(diff, methodology_ids)` to `(diff, axis_ids_by_axis: dict[str, list[str]])`
  and redact **every** axis's id values, each with its own token:

  | axis key | token |
  |---|---|
  | `methodology` | `[methodology]` |
  | `repo_context` | `[context]` |
  | `model` | `[model]` |
  | `runner` | `[runner]` |

  Reuse the existing `re.escape` + case-insensitive substitution loop, once per
  axis. Keep stripping instruction-file hunks (`CLAUDE.md`, `AGENTS.md`,
  `.github/copilot-instructions.md`, the `.claude/…` / `.github/agents/`
  prefixes): those files are laid down by **both** the methodology and the
  repo-context, so the existing `_is_methodology_file` filter already covers both
  axes — rename it `_is_instruction_file` for honesty, behavior unchanged. Order
  the substitutions longest-id-first within each axis so a short id that is a
  substring of a longer one doesn't partially mask it.

### 2. `core/db.py` — enumerate cells and fetch a cell's trials

- **`list_grading_cells(conn, axis)`** — generalize `list_grading_tasks`.
  Group passing trials by the *other* axes (always `task_id`, plus the three of
  `methodology_id, repo_context_id, model, runner` that are **not** `axis`),
  `HAVING COUNT(DISTINCT <axis-column>) >= 2`. Return one dict per gradable cell
  containing every fixed-axis value (so the frontend can render and re-query it),
  e.g. for `axis="model"`:

  ```python
  {"task_id": ..., "methodology_id": ..., "repo_context_id": ..., "runner": ...,
   "n_values": <distinct models in the cell>}
  ```

  Build the column list dynamically from `axis` (whitelist against `AXIS_FIELDS`
  to keep the SQL injection-safe). Keep `list_grading_tasks` as a thin wrapper
  (`axis="methodology"`) if anything else still calls it, or migrate callers.

- **`list_passing_trials(conn, *, task_id, methodology_id=None,
  repo_context_id=None, model=None, runner=None)`** — extend to filter a
  fully-specified cell. The comparison axis is left unconstrained (its kwarg is
  `None`); every other axis is pinned. Build the `WHERE` clause from the non-None
  kwargs (still joined to `gate_result` on `passed = 1`). Returns all passing
  trials in the cell, varying only the comparison axis.

### 3. `ui/server.py` — axis-general endpoints

- **`GET /api/axes`** → the comparable axes that actually have ≥1 gradable cell.
  Shape: `[{"axis": "methodology", "n_cells": 3}, ...]`.
- **`GET /api/cells?axis=<axis>`** → `list_grading_cells(conn, axis)` results, so
  the frontend can offer cascading pickers for the fixed axes.
- **`GET /api/pairs?axis=<axis>&task=<t>&methodology=<m>&repo_context=<c>&model=<mod>&runner=<r>`**
  — the comparison axis's own param is ignored/absent; the other axes pin the
  cell. Call the extended `list_passing_trials(...)`, then
  `generate_pairs(trials, run_results, axis=axis)`. Build `axis_ids_by_axis` from
  the trials in the cell (collect the distinct id values for each axis present)
  and pass it to `anonymize_diff` so **all** axis ids are blinded.
- **`SessionState`** — store `axis: str` and the fixed cell (`task_id` + the
  pinned axis values) instead of just `(task_id, model)`.
- **Reveal** — key the tally by the comparison axis's value (use
  `getattr(trial, AXIS_FIELDS[axis])`), not `methodology_id`. Include the axis
  name and the fixed cell in the response so the UI can render the header.
- **Rename the record/response types off methodology:** `MethodologyRecord` →
  `AxisValueRecord` (fields unchanged: `wins/losses/ties`); `RevealPair`'s
  `left_methodology_id` / `right_methodology_id` → `left_value` / `right_value`;
  `RevealResponse.summary: dict[str, AxisValueRecord]` keyed by axis value, and
  add `axis: str` + `cell: dict[str, str]`.

### 4. `ui/static/index.html` — axis picker → cascading cell pickers → grade

- First control: **comparison-axis picker** (populated from `/api/axes`).
- On axis change: fetch `/api/cells?axis=…` and render **cascading dropdowns for
  the other axes** (task + the three non-comparison axes) so the user pins a
  single cell. Grade button enabled once a cell with ≥2 values is selected.
- `/api/pairs` fetch includes `axis` + the pinned axis params.
- Reveal header reads **"comparing &lt;axis&gt; within &lt;fixed cell&gt;"**
  (e.g. *comparing model within task=pyvrp-A · methodology=superpowers ·
  repo_context=none · runner=claude-code*). Reveal table rows are keyed by the
  comparison axis's value.

## Tests (scope: pairwise unit + server TestClient)

- **`tests/test_pairwise.py`**
  - `anonymize_diff` redacts **every** axis id: build a diff embedding a
    methodology id, a repo_context id, a model id, and a runner id; assert none
    survive and that each is replaced by its own token.
  - `generate_pairs` groups by the **chosen axis**: a one-cell trial list whose
    only varying axis is `model` produces pairs across distinct model values;
    repeat for `axis="repo_context"`.
- **`tests/test_server.py`** (Starlette `TestClient` over the FastAPI `app`,
  seeded in-memory / temp `results.db` with passing `gate_result` rows):
  - `/api/cells?axis=model` lists a cell that has ≥2 models, and omits a cell
    with only 1.
  - `/api/pairs?axis=model&…` filters to **exactly one cell** — insert a decoy
    trial in a different cell and assert it never appears in the returned pairs.
  - Returned diffs contain **no** axis id substrings (methodology, repo_context,
    model, runner).

## What NOT to do

- Don't add multi-rep sampling or Bradley-Terry — that's P3.5 (which layers on
  top of this axis-generality).
- Don't implement cross-cell comparison or axis composition — exactly one axis
  varies; all others are pinned.
- Don't touch the matrix/executor/runner code from Parts 1–2.
