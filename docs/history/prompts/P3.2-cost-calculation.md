## Context

setup-bench currently uses Claude's self-reported `total_cost_usd` as the cost
metric. This varies by account tier, caching state, and billing quirks, making
it unreliable for cross-model and cross-setup comparisons.

The research report (`docs/research-eval-frameworks.md` §5) is unambiguous:
*"AI Agents That Matter"* shows accuracy-only evaluation rewards expensive
setups. Standard practice: compute USD from token counts × published API rates
for reproducible, comparable cost. Self-reported cost becomes a secondary
reference value.

## What to build

### 1. Create `cost/pricing.py` — model pricing table

Create a new module `cost/pricing.py` with a pricing table mapping model IDs to
per-token rates. Structure:

```python
@dataclass
class ModelPricing:
    input_per_mtok: float     # USD per 1M input tokens
    output_per_mtok: float    # USD per 1M output tokens
    cache_read_per_mtok: float  # USD per 1M cache-read tokens

PRICING: dict[str, ModelPricing] = { ... }
```

Populate with current Anthropic API pricing. Check the Anthropic pricing page
for the latest rates. Include at minimum:

- `claude-sonnet-4-6` (and aliases like `sonnet`)
- `claude-opus-4-8` (and aliases like `opus`)
- `claude-haiku-4-5` (and aliases like `haiku`)
- Older models that might appear in existing results: `claude-sonnet-4-5`,
  `claude-sonnet-3-5`

Add a function:

```python
def compute_api_rate_usd(
    model: str,
    input_tokens: int,
    output_tokens: int,
    cache_read_tokens: int,
) -> float | None:
```

Returns the computed USD cost, or `None` if the model isn't in the pricing table
(with a logged warning). The function should try exact match first, then try
matching known aliases (e.g., `sonnet` → `claude-sonnet-4-6`).

### 2. Modify `runners/claude_code.py` — use API-rate pricing

In `ClaudeCodeRunner.execute()`, after parsing Claude output (around line 70),
change how `CostRecord` is built:

**Before:**
```python
self.last_cost = CostRecord(
    trial_id=trial.id,
    native_unit="usd_imputed",
    native_amount=usage.total_cost_usd,
    usd_equiv=usage.total_cost_usd,
    ...
)
```

**After:**
```python
from cost.pricing import compute_api_rate_usd

api_usd = compute_api_rate_usd(
    trial.model,
    usage.input_tokens,
    usage.output_tokens,
    usage.cache_read_tokens,
)

self.last_cost = CostRecord(
    trial_id=trial.id,
    native_unit="usd_self_reported",
    native_amount=usage.total_cost_usd,
    usd_equiv=api_usd if api_usd is not None else usage.total_cost_usd,
    ...
)
```

Key points:
- `native_unit` changes to `"usd_self_reported"` (more descriptive)
- `native_amount` stays as Claude's self-reported cost
- `usd_equiv` uses the API-rate computation; falls back to self-reported if
  the model isn't in the pricing table
- Token fields stay the same (they're already captured correctly)

### 3. No schema changes needed

`CostRecord` already has `native_unit`, `native_amount`, `usd_equiv`, and all
token fields. The semantics shift but the structure is unchanged. Existing data
in `results.db` from prior runs will have `native_unit="usd_imputed"` — this is
fine; the old data is still valid, just computed differently.

## What NOT to do

- Don't add Pareto frontier visualization — that's a reporting concern for later.
- Don't modify the DB schema or `CostRecord` model.
- Don't touch wall-clock handling — it's already captured in `RunResult.wall_seconds`
  and is a secondary metric.
- Don't add pricing for non-Anthropic models yet (Copilot, etc.) — they can be
  added when those runners are actively used.
