# P3.4 — Gate System Overhaul

> **Studio adjustment.** Multi-file change touching models, DB, gate logic,
> executor, and UI — route through `studio-conductor` for the plan, then
> `studio-executor` for implementation.

> **Dependency:** Execute after P3.3 (axis refactor), since both modify
> `TaskSpec`, `Trial`, DB schema, and the executor.

## Context

setup-bench currently has a single gate: held-out tests (`grading/gate.py`). A
trial either passes or fails, and only passing trials enter pairwise grading.

The research report (`docs/research-eval-frameworks.md` §Gate structure) says:
*"Three hard gates in sequence: compile → visible tests → hidden tests."* The
key insight: compile failures are cheap to detect and shouldn't require running
the full test suite. Visible tests give the agent feedback during development.
Hidden tests are the definitive quality metric.

The research also says: *"Invest disproportionately in hidden-test strength"* —
weak hidden tests reorder rankings (31.08% of SWE-bench passing patches pass
weak tests).

## What to build

### 1. Expand `TaskSpec` — `core/models.py`

Add two optional fields:

```python
@dataclass
class TaskSpec:
    id: str
    repo_url: str
    base_commit: str
    instruction: str
    run_cmd: str                        # hidden test command (existing)
    held_out_tests_path: str            # existing
    reference_diff_path: str            # existing
    build_cmd: str | None = None        # NEW — compile/build gate
    visible_test_cmd: str | None = None # NEW — visible test gate
```

Both default to `None` (skip that gate). Existing tasks work unchanged.

### 2. Expand `GateResult` — `core/models.py`

Replace the flat model with a structured scorecard:

```python
@dataclass
class GateResult:
    trial_id: str
    passed: bool              # rollup: True only if hidden tests pass

    compile_passed: bool | None = None
    compile_output: str | None = None

    visible_passed: bool | None = None
    visible_output: str | None = None

    hidden_passed: bool | None = None
    hidden_output: str | None = None
```

The `passed` field is the rollup (= `hidden_passed` when hidden tests run,
preserving backward compatibility). `None` means that gate was skipped (no
command configured).

**Remove the old `test_output` field.** Its content moves to `hidden_output`.

### 3. Update DB schema — `core/db.py`

Replace the `gate_result` table:

```sql
CREATE TABLE IF NOT EXISTS gate_result (
    trial_id TEXT PRIMARY KEY,
    passed INTEGER NOT NULL,
    compile_passed INTEGER,
    compile_output TEXT,
    visible_passed INTEGER,
    visible_output TEXT,
    hidden_passed INTEGER,
    hidden_output TEXT
);
```

All new columns are nullable (existing rows from pre-P3.4 runs will have NULL).
Update `insert_gate_result()` and `get_gate_result()` to handle the new fields.

Also update `task_spec` table to include `build_cmd` and `visible_test_cmd`
(both nullable TEXT).

### 4. Rewrite `grading/gate.py`

The current `apply()` function runs held-out tests. Replace with a three-stage
pipeline:

```python
def apply(trial: Trial, worktree_path: Path, task: TaskSpec) -> GateResult:
    result = GateResult(trial_id=trial.id, passed=False)

    # Stage 1: Compile gate
    if task.build_cmd:
        compile_ok, compile_out = _run_command(task.build_cmd, worktree_path)
        result.compile_passed = compile_ok
        result.compile_output = compile_out
        if not compile_ok:
            # Fail fast — no point running tests if build fails
            return result

    # Stage 2: Visible test gate
    if task.visible_test_cmd:
        visible_ok, visible_out = _run_command(task.visible_test_cmd, worktree_path)
        result.visible_passed = visible_ok
        result.visible_output = visible_out
        # Don't fail-fast here — still run hidden tests for the scorecard

    # Stage 3: Hidden test gate (existing logic)
    hidden_ok, hidden_out = _run_hidden_tests(trial, worktree_path, task)
    result.hidden_passed = hidden_ok
    result.hidden_output = hidden_out
    result.passed = hidden_ok

    return result
```

Extract the existing held-out test logic into `_run_hidden_tests()` — it copies
tests into the worktree, runs `task.run_cmd`, captures output, cleans up. This
is the current `apply()` body, just extracted.

Add a helper `_run_command(cmd, cwd)` that runs a shell command and returns
`(passed: bool, output: str)`.

**Important:** The compile gate does NOT copy any files into the worktree — it
just runs the build command against whatever the agent produced. Only the hidden
test gate copies held-out tests.

### 5. Update executor — `core/executor.py`

No logic changes needed beyond passing the new TaskSpec fields through. The
`gate_apply()` call already receives the full `TaskSpec`. Just ensure the new
`GateResult` fields are stored correctly.

### 6. Update UI — `ui/server.py` and `ui/static/`

#### API changes

Add gate scorecard to the pair response. In `/api/pairs`, for each trial, fetch
the `GateResult` and include it:

```python
class GateScorecard(BaseModel):
    compile_passed: bool | None
    visible_passed: bool | None
    hidden_passed: bool | None

class BlindDiffResponse(BaseModel):
    label: str
    diff: str
    proxy: DiffProxy
    gate: GateScorecard   # NEW
```

#### UI changes

Render the gate scorecard as colored badges next to each diff header:

- **Build:** green checkmark / red X / gray dash (skipped)
- **Visible:** green / red / gray
- **Hidden:** green / red / gray

Keep them visually secondary — the diff is the main content. Place them in a
small row above or beside the diff header.

### 7. Update task YAML files

Add `build_cmd` and `visible_test_cmd` to the three PyVRP tasks. For PyVRP:

- `build_cmd`: `"pip install -e . 2>&1"` (compiles C++ extensions via
  scikit-build; if this fails, the code doesn't build)
- `visible_test_cmd`: `null` (no visible tests currently — the agent only gets
  the instruction text)

Example for `tasks/pyvrp-A/task.yaml`:
```yaml
id: pyvrp-A
repo_url: https://github.com/PyVRP/PyVRP
base_commit: 5871a0c1a8827bd84067bd4edf27fa6fa1cbfbdd
instruction: |
  Add a ReplaceGroup local-search operator ...
build_cmd: "pip install -e . 2>&1"
visible_test_cmd: null
run_cmd: "pytest tests/search/test_ReplaceGroup.py -v"
held_out_tests_path: tasks/pyvrp-A/held_out_tests
reference_diff_path: tasks/pyvrp-A/reference.diff
```

Note: `pip install -e .` for PyVRP triggers the CMake/C++ build. If the agent's
code has syntax errors or missing includes, this fails. This is a genuinely
useful early signal.

## What NOT to do

- Don't implement FAIL_TO_PASS / PASS_TO_PASS categorization within hidden
  tests — that's a task-design concern handled in P3.6.
- Don't change pairwise eligibility logic — hidden test pass remains the gate.
- Don't add new assertions for the compile gate's output format — just capture
  stdout+stderr as a string.
