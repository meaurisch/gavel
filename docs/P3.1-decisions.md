# P3.1 — Implementation Decisions

**Date:** 2026-06-24

For each of the 6 action points from the brainstorming session, this document
records: what the research said, how it affected the original intention, and what
the final prompt delivers.

---

## a. Axis Refactor → REFINE

**Original intention:** Split "setup" into "methodology" and "repo-context" as
two independent axes, making the trial matrix 5-dimensional.

**What the research says:** The research recommends separating methodology from
repo-context — *"Put anything repo-specific in the fixed environment, not in the
setup, so you're measuring the general methodology."* It also mandates a no-setup
baseline cell. The initial reading suggested making repo-context per-task only
(not an axis). However, the user clarified that **all axes are comparison targets**
— they want to compare different repo instructions too.

**Decision:** Keep the **5-axis matrix** (Task × Methodology × Repo-Context ×
Model × Runner, with reps). Both methodology and repo-context are independent
axes. The research insight is preserved: they're *separate* axes, not conflated
into one. This lets you design clean experiments:

- "Which methodology wins?" → fix repo-context, vary methodology
- "Which repo instructions win?" → fix methodology, vary repo-context
- "Which combination wins?" → full factorial

Repo-contexts have **task-affinity tags** (a pyvrp context only runs with pyvrp
tasks) to avoid nonsensical combinations. The CLI accepts `--full-matrix` to
override affinity filtering. `setups/` is renamed to `methodologies/` throughout
the codebase.

**Prompt:** P3.3 (5-axis refactor)

## b. Gate System Overhaul → REFINE

**Original intention:** Three soft gates (compile, visible tests, hidden tests).
All trials enter pairwise grading regardless. Gate scorecard shown alongside each
diff.

**What the research says:** Research recommends three **hard** gates in sequence,
no partial credit. The strongest finding: **hidden test quality is the #1
priority.** *"31.08% of SWE-bench passing patches pass weak tests"* and weak
tests *reorder rankings*.

**Decision:** Three-tier gate as a scorecard:

1. **Compile gate** (`build_cmd`) — catches build failures early and cheaply.
2. **Visible test gate** (`visible_test_cmd`) — tests the agent can see/use.
3. **Hidden test gate** (`run_cmd`) — held-out tests, the real grade.

Gates run in sequence with fail-fast. Hidden tests remain the eligibility gate
for pairwise grading (research is clear that rankings must use hard gates). The
full scorecard is visible in the grading UI, giving context for human judgment.

**Prompt:** P3.4 (gate system overhaul)

## c. Multi-Rep Pairwise Grading → CONFIRM + Bradley-Terry

**Original intention:** Random L-from-K×K sampling with balanced rep usage.
Seeded RNG. Win/loss/tie tallies. No statistical significance numbers.

**What the research says:** Bradley-Terry + bootstrap CIs are the standard for
converting pairwise comparisons into global rankings (used by LMSYS Chatbot
Arena). BT gives transitivity (beating a strong opponent counts more), stability,
and confidence intervals. Run ≥3 reps (ideally 5). Adopt skill-creator's
analyzer heuristics.

**Decision:** Include Bradley-Terry in P3.5. BT converts pairwise win/loss
results into a ranked score per methodology, with bootstrap 95% CIs. This fits
the decision-support framing — it answers "which methodology is best, and how
confident are we?" Ties counted as half-win/half-loss (LMSYS convention).

Also: multi-rep balanced sampling, per-setup pass rate, analyzer flags
(non-discriminating tasks, flaky tasks, cost/quality tradeoffs).

**Prompt:** P3.5 (multi-rep pairwise + BT)

## d. Cost Calculation Refactor → CONFIRM

**Original intention:** Compute USD from token counts × published API rates.

**What the research says:** Strongly confirms. *"AI Agents That Matter"* shows
accuracy-only evaluation rewards expensive setups. Log USD, tokens, tool-call
count, wall-clock. Note caching effects.

**Decision:** Add `cost/pricing.py` with model pricing table. Compute `usd_equiv`
from tokens × API rates instead of self-reported cost. Keep self-reported in
`native_amount` for comparison. Wall clock (already captured in
`RunResult.wall_seconds`) framed as a secondary metric — inherently noisy due to
machine load, but useful as a rough signal.

**Prompt:** P3.2 (cost refactor) — first in sequence because fully independent.

## e. Test Set Quality → CONFIRM

**Original intention:** Apply research to improve task design, update PyVRP
tasks, create guidance, consider validation tooling.

**What the research says:** Target 30–70% pass rate for discriminative tasks.
FAIL_TO_PASS / PASS_TO_PASS categorization. Augment hidden tests. Label
difficulty. Base tasks on real failures. *"The strength of your hidden tests
directly determines whether your ranking is real."*

**Decision:** Task design guide + validation tooling + difficulty labels + post-
calibration analysis.

**Prompt:** P3.6 (test set quality)
